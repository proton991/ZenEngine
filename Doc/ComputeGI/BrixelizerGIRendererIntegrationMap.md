# Distance-field renderer integration map

Status, 2026-10-28: this map is historical. Milestones 3 to 5 implemented it and removed the software BVH, brick and retrace paths it names; [the execution record](BrixelizerGIExecution.md) describes the integrated renderer.

This is a read-only implementation map for milestone 3, prepared against the then-current renderer while milestone 2 quality and construction work continued. It records the next integration boundaries; it does not enable a renderer path or qualify a preset. Native fixture evidence remains in [the field experiment](BrixelizerGIFieldExperiment.md), and acceptance requirements remain in [the implementation plan](BrixelizerGIImplementationPlan.md).

## Provider and result contract

`hybrid_provider.glsl` currently exposes `HybridRayResult { bool hit; position; normal; cell; }`. Its Compute default is `SoftwareTraceRay`; the brick define is an additional gather path, and mixed HW variants still include software traversal. Add a separate field-provider define while retaining the archived baseline for comparison. Reusing `HYBRID_BRICK_TRAVERSAL` would also activate triangle-retrace queues and inline near-light retracing, defeating the migration.

The adapter must preserve `HIT`, `COVERED_MISS`, and `UNAVAILABLE` from `DistanceFieldTraceResult`. HW and retained reference adapters can supply hit/covered-miss, but every consumer must test the explicit status rather than equating `!hit` with visibility. A hit with a zero measured normal still blocks visibility; it has no usable radiance orientation. An unavailable query has neither a hit surface nor an environment contribution. Preserve diagnostic reason, distance samples and work counts separately from ray counts.

`HybridTraceOrigin` lives in `scene_ray_geometry.glsl`, which also declares the full triangle/material interface. Extract only the shared origin-offset math for field-only consumers. Do not inherit occupancy-brick skip-start behavior, add a fake cell-face normal, or include software triangle resources just to obtain this helper. Field-origin bias needs a measured relation to the field hit band and sample spacing, with both-side/self-hit tests.

The current field uniform/resources use descriptor set 4. This coexists with HW query geometry and metadata in sets 5/6, but conflicts with shadow-map resources in set 4. Field tracing belongs in sky/gather passes. Direct-light injection and material composition should continue using maps or HW and need no field bindings.

Supporting consumers requiring validity propagation are `probe_temporal.glsl`, `probe_integrate.comp`, `probe_specular_resolve.comp`, `probe_pixel_temporal.comp`, the probe spatial filters, `hybrid_temporal.glsl`, the hybrid spatial filters, and `hybrid_diffuse_upsample.comp`. Their current channels represent visibility, rejection, or history length, not generic field availability.

In particular, clearing an unavailable probe's `position.w` prevents `probe_temporal.glsl` from accumulating it, but `probe_integrate.comp` can substitute a nearby facing probe when no compatible one remains. Its pixel temporal pass then starts a new diffuse history with length one. Specular resolve uses alpha `-1` for a missing block sample; pixel temporal may retain prior history or substitute diffuse sky visibility. These existing sampling fallbacks must not conceal a field coverage/iteration failure. Use explicit per-feature validity through the gather output, or a distinct failure sentinel whose handling is audited through every filter and composition stage. Reuse of history requires the same committed visibility generation; it must not lengthen a history as though an unavailable sample were observed. Before valid history exists, the selected HW/PBR fallback must be explicit.

The material outputs in `deferred_lighting.glsl` and `forward_material.glsl` already compose escaped diffuse, bounced diffuse, specular visibility and reflected radiance separately. Retain that accounting. If per-pixel fallback is introduced, preserve a validity mask to composition; clearing receiver identity alone can select the unoccluded forward-material fallback and therefore does not implement the unavailable contract by itself.

Calibration shaders (`hybrid_check.comp`, `hit_radiance_check.comp`, `hit_light_cache_check.comp`, and `brick_trace_check.comp`) construct the old result type directly. Update their adapters or keep an explicitly separate legacy type so a struct change does not leave stale tests compiling with wrong semantics.

## Radiance cache adaptation

The field visibility domain is independent of the bounded radiance cache. Map a field hit position to the cache cell only after tracing. In `hit_radiance.glsl`, `HitRadiance` currently tries the supplied cell, then its ray-side neighbor; `HitCachedLight` independently maps to the coarser class grid and may also try a neighbor. An outside-cache cell can therefore pull data from an edge cell. Add a world/cache-domain guard before **all** isotropic, reflectance and class-light lookups, including neighbor retries. An outside-cache hit remains `HIT`, returns zero cache radiance, and never clamps to an unrelated cell or becomes sky.

Inside the cache, retain `radiance.a` validity, cached owner-facing checks, surface-class compatibility and the bounded neighbor search. A field hit occurs in a distance band rather than at an exact triangle intersection; any cache correspondence adjustment must remain bounded and surface-compatible. A zero field gradient cannot be replaced by an arbitrary incoming-ray normal to satisfy the cache. It can reject radiance, or use a separately proven compatible cache surface normal while preserving the geometric visibility hit.

The isotropic cache excludes the first 31 cached scene lights. `HitCachedLight` adds those once using hit-point attenuation/cosine and reflectance; nearby lights retrace visibility while far lights use the class mask. Keep that split, current/previous light-cache evaluation, and the single final indirect-intensity multiplication. Field adaptation must not add an independent emission, environment or direct-light term on top of existing cached contributions.

`inject_radiance.glsl` presently ignores sky-cache alpha and publishes occupied radiance cells valid. A sky producer validity marker alone is insufficient: injection must consume it, and downstream hit-radiance validity/history must honor it. Direct shadow maps or HW remain active for its ordinary light injection.

## Renderer preparation, publication and fallback

The production preparation owner is `VoxelGIRenderer::BuildRayQueryGraph` (`VoxelGIRenderer.cpp:705`). It currently prepares software BVH before optional bricks, prepares a software dummy even when unused, and treats pending software work with HW fallback. Replace that dependency in candidate mode: field construction and HW readiness are independent, and no candidate path calls `Prepare`, `PrepareUnused`, or binds software traversal. Keep per-feature HW masks and a distinct pending/failed reason.

`RendererServer::DispatchRenderWorkloads` (`RendererServer.cpp:103`) currently schedules preparation only in the Voxel-GI, non-diagnostic branch. A pending result sets `m_frameGI=false` and renders PBR. Its completion callback only calls `VoxelGIRenderer::OnRenderGraphExecuted` when `m_frameGI` is true. A progressive field that recorded work while pending would thus never receive its submission result if integrated under the existing boolean.

Schedule visibility preparation after a successful committed scene `Update` and render-graph `Begin`, independently of whether that frame can compose GI. For GI-enabled scene activation, it must continue when the effective renderer is PBR fallback or selected feature providers are HW; diagnostic rendering must not accidentally stall preparation. Track whether visibility construction was attempted separately from whether GI lighting was recorded, and deliver exactly one submission/failure callback for that attempted work. Do not publish stale radiance flags from a frame that did not call the cache builder. Explicitly disabling GI can retain or pause the already owned field; switching Compute/HW must not destroy it.

Current PBR fallback is the minimum PBR tier: it calls `DeferredLightingRenderer::BuildRenderGraph(view)` without a shadow owner, and `AddLightingPass` only binds maps through a non-null `voxelGI`. Preparing maps alone will not apply them. To meet the plan's temporary PBR/maps behavior, separate direct-shadow composition binding/variant selection from availability of indirect GI. Preserve the existing fallback reason and do not pretend a pending field is a permanent failure.

`VoxelGIRenderer::BuildRenderGraph` (`:790`) decides sky recomputation from voxelizer geometry and environment revisions; `HybridGIRenderer::BuildRenderGraph` (`:341`) resets for scene/provider/settings changes. Field publication can change visibility with the same scene revision, so propagate a committed field generation/coverage stamp into sky injection, radiance history, both gathers and learned guides. Commit the consumed stamp only after the corresponding graph submission succeeds. Changes to full-scene coverage, local-detail availability or normal/tolerance representation also affect that stamp. Old generations remain usable only while their committed-scene contract is still valid; an edited blocker cannot be ignored while a replacement builds.

`RendererServerSettings.cpp` currently destroys the whole VoxelGI owner for radiance-grid/voxelizer/reflectance-resource rebuilds. A future owner placement must account for this if retaining field data across unrelated cache rebuilds is intended. Ordinary Compute/HW switches do not trigger `RequiresVoxelGIRebuild`, so no additional rebuild is needed for provider toggles. Scene replacement must still retire/cancel old field snapshots safely.

## Variants and bindings

`VoxelGIRenderer::BindHardwareRayInputs` (`:1045`) currently also binds software traversal. `HybridGIRenderer::BindTraceInputs` (`:224`) and `ScreenProbeGather::BindTraceInputs` (`:282`) rely on it for mixed variants. Split field binding from pure HW geometry binding; mixed field/HW variants bind both directly, with no software dummy. Sky-cache receivers separately need `TriangleRecords` plus vertex/index/node buffers for owner-point reconstruction.

| Family | Candidate variants needed |
| --- | --- |
| Sky cache | Field and field-counts. Existing HW and HW-counts remain. |
| Pixel gather | Field full, half-resolution, fallback-list, with/without counts; mixed HW/field full with/without counts. The current renderer only chooses half resolution when no gather feature uses HW. Preserve that policy initially. |
| Pixel reference and guide capture | Reference accumulation can use the normal field kernel's runtime reference mode because its special brick variant exists only for inline triangle retracing. Preserve the `StoreGuideTracePrograms` exact-guide specialization alias for every applicable new family. |
| Probe gather | `ProbeTraceField`, `ProbeTraceHardwareField`, `ProbeSpecularTraceField`, `ProbeSpecularTraceHardwareField`. Ordinary non-brick temporal/filter paths need validity changes, not retrace variants. |
| Injection/composition | Reuse maps/HW variants. Candidate mode must never select software shadows, including averaged-reflectance, capture, counts, receiver-visibility, forward and forward-scatter combinations. |

Feature bits remain SKY=1, SPECULAR=2, SKY_CACHE=4, BOUNCE=8, REFLECTION=16, SHADOWS=32. SKY/BOUNCE share a query only when the resolved provider is the same; SPECULAR/REFLECTION follow the same rule. A mixed shader's BOUNCE bit also controls near-light correction. Do not infer a single all-feature backend from the presence of any HW bit.

During candidate-field execution, bypass `HybridRetrace`, `HybridFallbackRetrace`, the reference inline `BrickRetraceTriangles` branch, `ProbeRetraceBricks`, `ProbeTemporalBricks`, all retrace queue allocations/reset/merge passes, and their `SoftwareTraceOpaqueRay` calls. Retain the archived old path only for baseline comparison until final removal. No field variant should define `HYBRID_BRICK_TRAVERSAL` or `PROBE_RETRACE`.

Initialization warmups must cover chosen field kernels so the first Compute toggle does not compile them synchronously. Settings validation/loading, `LightingBackendControls.cpp`, runtime preparation text, editor snapshots, profiling JSON and lighting-capture JSON currently name triangles/bricks/software-BVH preparation. Add distinct candidate field status and measured work/memory counters during integration, then remove obsolete UI/settings in milestone 5. `IsPreparingGI` also gates measured-frame counting and headless frame limits, so it must distinguish required pending visibility from optional background prewarm while HW already renders correctly.

## Next small integration after the quality gates

1. Add the result adapter and test it through the **actual sky-cache and hit-radiance includes** before enabling gather selection. Use a full-coverage field around a smaller cache, an outside-cache opaque blocker, an in-cache compatible surface, an unknown leaf, and an exhausted trace budget. Assert blocked sky/local-light visibility, zero out-of-cache radiance, preserved facing rejection, and explicit invalid output for unavailable. Include finite light segments that cross the cache boundary and stop before/after a blocker. This is the smallest consumer contract slice that the standalone tracer tests do not cover.
2. Wire production field preparation/publication and submission callbacks while keeping selected rendering on the existing HW/PBR path. Test pending-to-ready across multiple frames, rejected submission, scene replacement/edits, a HW-to-Compute toggle, and unchanged-scene field-generation publication. Verify there is no software preparation/allocation in candidate mode. This isolates lifecycle faults from estimator changes.
3. Enable one full-resolution pixel gather path with maps for direct shadows, explicit validity propagation and the measured local-detail selection. Capture escaped/bounced diffuse, specular visibility and reflection separately against retained references. Then extend the same adapter to mixed masks, probes, half resolution and reference/count variants. This order does not drop the required final probe path; it makes the first renderer comparison attributable.

No renderer/shader source was changed to produce this map, and no build/GPU run was performed for it. The plotted visibility readback is diagnostic evidence from the separately coordinated native run, not a full-GI comparison.
