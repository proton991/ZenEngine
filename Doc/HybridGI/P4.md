# P4 hardware ray queries

Implemented on 2026-10-07. The hardware provider now supplies per-pixel sky visibility, specular occlusion, and the voxel sky cache. The radiance cache and cone bounce remain in use; hit-radiance bounce is P5. **P4 acceptance remains open**: at four samples per pixel the hall's full-image shipping reconstruction still misses its 99th-percentile and exact-zero limits (bias and RMS now pass; see [Hall full-image reconstruction](#hall-full-image-reconstruction-2026-10-09)); against the full-image [ground truth](#ground-truth-comparison-2026-10-09) the tier reference passes on three of four views but misses the per-pixel limit on the hotel-room hall; and the RX 7900 XT, non-RT and MoltenVK targets have not been tested. A nine-environment sweep against the ground truth (2026-10-10) finds the shipping reconstruction failing in every hall view; the remaining gaps and the steps to close them are in [P4 gaps](P4Gaps.md). An AMD Radeon iGPU was tested on 2026-10-08; see [Review fixes](#review-fixes-2026-10-08).

## Implementation

- The RHI exposes enabled buffer-device-address, acceleration-structure, ray-query, build-queue, float3-format, scratch-alignment and geometry/count capabilities. Hardware shaders are separate programs, registered only when this capability bundle is usable. `--disable-rt` is still a device-creation override.
- `RHIAccelerationStructure` uses the existing resource identity, reference ownership, resource factory, allocator and executor conventions. Build commands copy geometry descriptions into command storage. TLAS dependencies retain their BLAS objects. Vulkan implements size queries, storage/address creation, build/update validation and ordinary AS descriptors.
- Graph AS accesses use the underlying storage allocation, so the existing submission history tracks their writers and readers. Builds declare geometry/instance inputs, update sources, indirect BLAS reads, destination writes and scratch reuse. Shader queries declare TLAS and indirect BLAS reads at the shader stage. Builds and the shipping hardware queries start on graphics.
- `SceneRayQuery` shares a BLAS per mesh. Vertex/index buffers are the raster snapshot. Deformation replaces the scene-wide vertex buffer, so each mesh keeps a hash of its committed positions over its referenced vertex range: unchanged meshes keep their BLAS, deformed meshes are refit in place, and a BLAS is rebuilt in place after 16 consecutive refits. Changed topology/index storage or opacity mode rebuilds. The TLAS is rebuilt for every generation. Build scratch is a grow-only buffer shared by generations; memory accounting counts shared BLASes once. Scene replacement drops the snapshot. Geometry and surface revisions trigger preparation. (Revised 2026-10-08; see [Review fixes](#review-fixes-2026-10-08).)
- Only alpha-mask geometry is non-opaque; the candidate shader applies base-color or specular-glossiness alpha, vertex alpha, UV selection, transforms, sampler and cutoff at explicit LOD zero, and rejected candidates continue traversal. Every other surface is opaque. Both faces of every surface block, whatever its raster sidedness, as in the voxel provider and the CPU reference. Blend/transmission surfaces are opaque query blockers. Closest hits include instance, primitive, material, barycentrics, normal, raster facing and a 64-bit snapshot generation encoded as two uints.
- Visibility ranges use full scene bounds, independently of voxel bounds. Triangle origins use normal-directed floating-point offsets plus the measured receiver depth-quantization error. Hardware reconstruction omits the voxel occupied-start guide responsible for D2 squares.
- Requested and selected providers, enabled features, readiness, generation, AS bytes and reason are written to lighting capture metadata. Provider changes reset incompatible histories. Failed execution invalidates the prepared snapshot; a blocked backend cannot report a ready query scene.

`voxel_gi_acceleration_structure_budget_mb` optionally caps AS storage, scratch and query metadata, including active/prepared/retiring generations. Zero leaves the cap unset. Accounting conservatively counts shared BLAS storage in each generation. Rejection selects voxel GI and reports `acceleration_structure_budget`, without changing resolution or sample counts. This is **not** the total GI memory cap still required by P0/P8.

## Hotel-room noise (2026-10-08)

`Environments/hotel_room_1k.hdr` exposed severe sampling variance. In frozen captures, history reached 32 and `reset_reason` was `none`, so repeated history invalidation was not the cause. The prefiltered level-zero environment contains values up to 49,856. Four cosine samples rarely hit its small bright sources: individual raw top-floor estimates reached 3,848 while the converged floor mean was approximately 0.105. Temporal averaging and the existing spatial filter could not reliably remove those rare large contributions.

The sky estimator now uses equal proportions of environment-luminance and cosine samples, weighted by the full mixture PDF (changed to three environment samples per cosine sample on 2026-10-09; see [Hall full-image reconstruction](#hall-full-image-reconstruction-2026-10-09)). The default remains four diffuse samples per pixel. One-sample mode randomly chooses a proposal; two/four-sample and reference modes split the proposals equally. Black environments use cosine sampling. No radiance clipping was added. The deterministic 64-direction voxel sky cache uses the same mixture, without extending ray queries to additional GI features. Diffuse spatial filtering uses a tighter luminance tolerance (1σ instead of 4σ) to preserve sharp visibility boundaries from small HDR sources; specular filtering retains 4σ.

Two GPU compute passes build row/column cumulative distributions from the existing prefiltered cubemap, including the cube-to-solid-angle Jacobian. They use the existing environment revision and successful-execution invalidation path. Shared per-renderer storage is approximately 6.02 MiB (six 512×512 faces plus CDF endpoints), with no per-view copy. Sampling and PDF evaluation use the stored CDF intervals and respect environment rotation/orientation. This follows the standard [environment importance sampling](https://pbr-book.org/4ed/Light_Sources/Infinite_Area_Lights) and [multiple importance sampling](https://pbr-book.org/4ed/Light_Transport_I_Surface_Reflection/A_Better_Path_Tracer) estimators.

Before/after captures use the same frozen settings described above and compare against a 1024-sample × 64-frame mixture-sampled reference. A pure-cosine reference at that count was itself visibly noisy for this HDR. Independent numerical cubemap quadrature on unoccluded bright-source fixtures checks the new estimator's scale and orientation. Errors below are RGB errors normalized by each region's reference mean.

Found by the AMD run:

- **Instance-buffer alignment.** Vulkan requires 16-byte-aligned instance data, but buffer memory requirements did not guarantee it: the AMD iGPU placed the TLAS instance buffer off a 16-byte boundary and the build was rejected before recording. The Vulkan allocator now creates every AS-input buffer with at least 16-byte alignment (`vmaCreateBufferWithAlignment`).

## Hall full-image reconstruction (2026-10-09)

At four samples, Papermill's hall view failed the shipping limits over all receivers (RMS 8.59%, P99 31.42%, three exact zeros against a fresh reference) while both floor regions passed. Three changes bring RMS within the limit and P99 to 21.61%; the hall still fails P99 and has eight exact zeros. Eight samples per pixel pass every limit.

### Diagnosis

- The full-image region mean (0.047) is a third of the floor mean, so absolute errors on bright surfaces dominate. The floor's own 99th-percentile error alone exceeded the full-image limit.
- Most error is residual noise rather than filter bias. With a converged history (256-frame limit, 512 frames), the same reconstruction gives RMS 3.1% and P99 11.2%. Unfiltered temporal output is unbiased (+0.01%) with RMS 35%.
- The filter blurred the curtains' normal-map shading: sky irradiance varies with the shading normal, and the normal weight could not separate that variation from noise.
- The luminance tolerance was already close to optimal: 0.6σ gives P99 31.8%, 1.5σ 22.0%, and removing the luminance test raises RMS to 23% (contact gradients smear). Relaxing the plane, geometric-normal or shading-normal tests changes P99 by less than 0.4 points.
- After the changes, residual errors concentrate on fine geometry that no spatial filter can legitimately average: foliage, flowers in the pots, hanging bowls, gathered curtain tops, rails, and the floor next to curtain and column bases. Small up-facing surfaces (2.3% of pixels) carry a quarter of the 99th-percentile errors; the filter reduces their noise only 1.7× (floor 7.5×, curtains 2.5×).
- The eight exact zeros are on ornament, lamp and plant facets whose neighbors all differ in geometric normal by more than 25° (dot products 0.3–0.7). Their histories hold no escaped ray in roughly 250 samples; the reference values are 11–38% of the region mean. They are statistical, not the D2 start-cell squares.

### Changes

| Change | Effect |
| --- | --- |
| Per-pixel sequence rotations are Owen-scrambled Sobol points in Morton pixel order ([Burley 2020](https://jcgt.org/published/0009/04/01/); [Ahmed and Wonka 2020](https://doi.org/10.1145/3414685.3417881)), replacing per-pixel hashes. Every aligned 2^k × 2^k block holds a stratified set, so the filter averages blue-noise error. | Hall RMS 8.60 → 7.87%, P99 31.5 → 29.0%. |
| The sky is filtered as a ratio to the unoccluded irradiance for the receiver's shading normal and remodulated by the center's value. The environment-columns pass also projects the level-zero environment onto order-2 spherical harmonics (48 partial sums, 7 KiB); the rows pass totals them. The temporal pass evaluates the normalized guide once per pixel into an RGBA16F transient. | Curtain detail is preserved. Hall RMS 6.93%; top full image 3.32 → 1.91%; hotel top full image 4.23 → 3.33%. |
| Three environment samples per cosine sample (`HYBRID_ENVIRONMENT_SHARE`), with the matching mixture PDF. One and two samples choose each proposal with those probabilities. The voxel sky cache uses 48 environment and 16 cosine directions. | Hall RMS 5.98%, P99 21.6%; improves all four views. |

Rejected during the investigation, each measured on both environments:

- Consecutive per-proposal sequence indices: better on Papermill, worse on the hotel room (hall RMS 15.4 → 17.6%).
- The existing PBR irradiance cube as the guide: Papermill matched, but the hotel room's small, very bright sources alias in its Riemann sum (hotel top floor RMS 40%, P99 198%). A GGX-prefiltered mip (narrow lobe) and the 1×1 roughness-one mip (ambient cube) lost most of the gain.
- Feeding the first filter iteration back into history (SVGF): −7.5% bias, because luminance stopping rejects rare bright samples and feedback compounds it.
- Resampled `L * cos` product sampling (8 or 16 candidates): hall RMS 14%, trace 3× slower; the brightest sky is mostly occluded from the hall.
- 87.5% environment samples: hall RMS 11%. A fixed upward cone as a third proposal: worse; the hall reaches the sky sideways through the arcades.
- The power heuristic: P99 21.4%, hotel hall slightly worse. A local-mean center value for edge stopping: worse on both environments.

## Ground-truth comparison (2026-10-09)

Rasterization and rays see different surfaces at 2.0% of hall pixels and 0.35% of top pixels (mostly alpha-masked foliage, which the rasterizer tests at a mip level and rays at level zero, and silhouettes). These pixels are excluded from the table and reported separately.

### Still open

- **Hotel hall, distant lamp-lit receivers.** Receivers nearer than 0.3 renderer units (87% of pixels) agree within 0.40% excess, and the floor passes. The far atrium lit directly by the lamps has 17–23% excess, growing with the receiver's depth-quantization error (standard-Z D32). Papermill's soft sky shows at most 1.3% at the same distances. Shading the engine's own reconstructed receivers in Mitsuba halves the error beyond 0.45 units but not between 0.30 and 0.45, so receiver precision explains only part of it. Next: a fixture with a sub-degree source, an occluder edge and a controlled receiver depth, and a reversed-Z experiment.
- Normal-mapped comparisons, bounce (P5) and final-image validation are not run yet.

## Reproduction

Build `scene_renderer_demo`, `RenderCoreTest`, `RayQueryIntegrationTest` and `ConeVoxelGIIntegrationTest`. Use `tools/requirements-gi-quality.txt`; run configuration-mutating captures sequentially.

```powershell
python tools/validate_hybrid_gi.py --exe build/x64-windows-msvc-debug/bin/scene_renderer_demo.exe --output build/hybrid-p4/fixtures --provider hardware --rt --allow-present-baseline
python tools/capture_hybrid_gi.py --exe build/x64-windows-msvc-debug/bin/scene_renderer_demo.exe --scene PATH/TO/Sponza/glTF/Sponza.gltf --output build/hybrid-p4/top --camera top --provider hardware --rt
python tools/capture_hybrid_gi.py --exe build/x64-windows-msvc-debug/bin/scene_renderer_demo.exe --scene PATH/TO/Sponza/glTF/Sponza.gltf --output build/hybrid-p4/top-reference --camera top --provider hardware --rt --reference-samples 1024
python tools/compare_hybrid_gi.py build/hybrid-p4/top build/hybrid-p4/top-reference
python tools/environment_reference.py --scene build/hybrid-p4/top.gltf --capture build/hybrid-p4/top-reference --samples 4096 --stride 64 --output build/hybrid-p4/top-cpu.npz
python tools/validate_hybrid_gi.py --exe build/x64-windows-msvc-debug/bin/scene_renderer_demo.exe --output build/hybrid-p4/sky-cache --sky-cache-check
$env:ZEN_VULKAN_DEVICE = "AMD Radeon"; python tools/validate_hybrid_gi.py --exe build/x64-windows-msvc-debug/bin/scene_renderer_demo.exe --output build/hybrid-p4/amd-fixtures --provider hardware --rt
```

`ZEN_VULKAN_DEVICE` also selects the adapter for test executables such as `RayQueryIntegrationTest`; remove it afterwards.

Ground truth ([plan](../HardwareRayQueryEnvironmentLightingPlan.md#ground-truth)): the renders are stored once, unchanged, in `build/ground-truth/dataset/` (ignored by Git): one per environment and camera, with `dataset.json` recording the scene and environment hashes, camera matrix and captured environment cube each depends on, and the archived fixture-gate report. Engine captures are not stored; [ground_truth_sweep.py](../../tools/ground_truth_sweep.py) regenerates them for the current build, refuses a capture that no longer matches its render, and writes `report.json` and `summary.md`. Run it with the Python environment from `tools/requirements-gi-quality.txt`.

```powershell
python tools/ground_truth_sweep.py --exe build/x64-windows-msvc-debug/bin/scene_renderer_demo.exe --scene PATH/TO/Sponza/glTF/Sponza.gltf --output build/ground-truth/runs/NAME
```

`--environments` and `--cameras` select views (default: all nine environments, both cameras, 72 captures in about 12 minutes); `--skip-shipping-gate` keeps only the normal-map-free comparison. For a view not in the dataset, gate the renderer on the analytic fixtures first, then render it; stored renders are never replaced:

```powershell
python tools/ground_truth_mitsuba.py --fixtures build/hybrid-p4/fixtures --output build/ground-truth/fixtures
python tools/ground_truth_sweep.py --exe ... --scene ... --environments NAME --render-missing --fixture-gate build/ground-truth/fixtures/fixtures.json
```

`--backend auto` (the default) uses Mitsuba's CUDA backend when an NVIDIA GPU is present (driver only; about 10 minutes per 960×540 view at 32768 samples on an RTX 5080, with the GPU mostly idle, so several views can render concurrently) and its CPU LLVM backend otherwise (about 12× slower; on Windows it finds Visual Studio's `LLVM-C.dll`, else set `DRJIT_LIBLLVM_PATH`). Both backends pass the fixture gate with identical values, and their Sponza hall results agree within sampling noise (0.25% RMS). CUDA is used only by this offline tool.

Repeat the camera captures with `--camera hall`; use 65536 samples for its sparse CPU comparison. `--as-budget-mb 1` reproduces Sponza's budget fallback. Omit `--rt` to exercise the hard feature override. Capture manifests fingerprint scene inputs, executable, configuration and shaders. Local logs and captures from this run are under `build/p4-*` and `build/hybrid-p4/`.
