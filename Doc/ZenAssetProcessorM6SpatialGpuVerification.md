# M6 spatial GPU integration checkpoint

24 October 2026. Cooked spatial packages now reach native images and material
sampling. The supported profile remains single-level, power-of-two RGBA8 with
linear clamp sampling and no anisotropy. This checkpoint verifies that profile
on the RTX 5080; broader M6 sampling and workload gates remain open.

The later [two-device native campaign](ZenAssetProcessorNativeNormalVerification.md)
finds that this same spatial material test fails on AMD Radeon(TM) Graphics:
142 alpha decisions change in each execution mode. Its NVIDIA result remains
exact. The results below retain their original NVIDIA scope; spatial parity on
AMD is a confirmed unresolved issue.

## Runtime changes

`TextureManager` shares one native image and upload for each immutable spatial
page within a scene load. Logical regions with the same format reuse a 2D view;
compatible linear/sRGB aliases use separate views of that image. Independent
loads retain independent native ownership. The loader validates physical byte
footprints, owner/view compatibility, region bounds and gutters, one explicit
mip, power-of-two extents and the explicit linear/clamp sampler before creating
the image. Mutable local pixel overrides continue to select standalone storage.

`TextureTransformData` now appends an integer region separately from its two
authored rows. Base, normal, feature and specular/glossiness bindings publish the
effective texture region. `MaterialData` grows from 1,264 to 1,632 bytes; its
last vector carries device sampling precision. `RenderScene` fills that value
on initial publication and updates. Live material updates reject a region or
sampler that no longer matches the selected logical view, without changing the
published material. Region changes participate in coverage invalidation.

Vulkan exposes `subTexelPrecisionBits` through `RHIGPUInfo`; the renderer uses
the reported value rather than assuming eight bits. Spatial uploads reject an
unreported value or a value beyond the supported FP32 fractional range of
1–23 bits. The shader rounds in logical texel space before adding the page
offset, then uses native filtering. Fragment gradients and normal-map tangent
reconstruction retain authored UVs. Ray-candidate alpha calls the shared,
explicit level-zero helper, including when invoked from a fragment shader.
The device limit describes sampling precision; the measured half-up candidate
is not a universal Vulkan rounding guarantee. See the
[Vulkan sampling specification](https://docs.vulkan.org/spec/latest/chapters/textures.html)
and the earlier [coordinate experiments](../../ZenAssetProcessor/docs/AtlasCoordinatePrecisionEvaluation.md).

## Verification

Windows, MSVC Release, Vulkan SDK 1.4.357.0, NVIDIA GeForce RTX 5080. Native runs
report eight subtexel bits. The build is `build/asset-integration-release` with
the sibling processor source override. All production material consumers rebuild
against the new layout, including raster, voxel and ray shaders.

| Check | Result | Scope |
| --- | --- | --- |
| Adapter, package/cache, material compatibility and animation-pointer checks | 56/56 | CPU records, publication and existing transforms |
| Importer material regressions | 9/9 | Existing color/data aliases, factors and tangent rules |
| Full RenderCore suite | 717/717 executed; 9 existing disabled | Upload, invalid bounds/samplers, sharing and view-failure behavior |
| Shader reflection | 23/23 | Material stride, normal flags, regions and precision offsets across raster/GI |
| Native texture integration | 6/6 | Two spatial cases and four existing array/anisotropy regressions |
| Cooked spatial rendering | 2/2 | 24 exact RGBA frame pairs, both execution modes |
| Existing cooked array rendering | 4/4 | 64 exact frame pairs in the first combined rendering run |
| Existing editor regressions | 8/8 | Rendering/picking, preview, recook rollback and failed upload |

The native spatial fixture uses different-sized 8x4 and 4x8 tiles, extruded
gutters, UNORM/sRGB views and an alias. Production uploads and the production
material shader compare 399,384 spatial/reference Vec4 pairs across inline and
threaded execution. Every floating channel matches exactly, and every
`alpha >= 0.5` decision agrees. Another 99,846 alias pairs match. These are
three sampling operations over two coordinate grids, not independent coverage
of every coordinate. The explicit alpha helper is exercised; this test does
not cast rays through a spatial alpha-mask scene.

The original `spatial_scene.gltf` fixture contains five instances, two material
variants, color/normal/occlusion maps, clearcoat normal maps and a repeating
standalone mask. It is generated by `generate_spatial_scene.py` using the shared
panel-fixture generator. Each source copy is removed after cooking and before
opening its package. Spatial on/off frames are exactly equal at 256x192 over
two variants and six camera views in each execution mode: 24 pairs and
4,718,592 RGBA channel comparisons. Nonblank and visible-variant assertions
pass. The final test also rejects invalid live edits to base/feature regions
and sampler selection, and confirms callers cannot override device precision.
Saved RGB captures independently compare exactly. Front, oblique/swapped and
far captures were visually inspected; the far case intentionally covers a
small visible footprint.

Native and editor runs report zero remaining VMA allocation bytes and no Vulkan
validation errors. All checked executables report no tracked CPU leaks. These
are correctness runs, not performance timing measurements.

## Allocation result and remaining gates

Both execution modes produce the same authored-image measurements:

| Mode | Native images | VMA allocation bytes |
| --- | ---: | ---: |
| Standalone | 7 | 623,616 |
| Spatial | 4 | 1,661,952 |

Power-of-two page padding increases allocation by 1,038,336 bytes in this fixture.
Fewer images therefore do not establish a memory or frame-time benefit. The
material-buffer growth above must also be included in future cost comparisons.
Spatial cooking stays opt-in and this checkpoint does not satisfy M6's workload
benefit gate. General mip chains, non-power-of-two tiles, anisotropy and block
compressed spatial pages remain outside this profile. The subsequent
[cooked spatial ray checkpoint](ZenAssetProcessorM6SpatialRayVerification.md)
verifies bounded alpha-query parity through production software/hardware
traversal in compute and fragment shader contexts. Full GI comparisons,
additional devices and production upload/frame cost still need their own
evidence. The previous lossy-compression and GI acceptance gaps are unchanged.

## Retained failures and evidence

The first shader compile used samplerless `textureSize` without enabling its
extension. It was corrected to query the existing combined sampler. The first
cooked rendering run produced exact comparisons but failed the nonblank guard
at the spatial fixture's farthest camera. Its spatial-only dolly distance changed
from -24 to -18; the zero-difference and nonblank gates were retained. Subsequent
runs pass all 24 pairs. The original failing log and captures remain available.

Evidence is under `build/asset-integration-release`:

- `m6-spatial-gpu-baseline/` and `m6-spatial-gpu.diff`: this checkpoint's delta,
  preserving the prior unrelated rendering work.
- `m6-spatial-gpu-build*.log`, `m6-spatial-gpu-regression-build.log` and
  `m6-spatial-gpu-rendering-build-*.log`: failed and successful builds.
- `m6-spatial-gpu-{common,rendercore,native,reflection,material-regression,editor-regression}.{log,xml}`.
- `m6-spatial-gpu-rendering.{log,xml}`: first combined run, including four passing
  array cases and the spatial nonblank failures.
- `m6-spatial-gpu-rendering-update.{log,xml}`: final spatial run with live-update
  checks; `m6-spatial-gpu-captures-final/`: packages, 48 PPM captures, resource
  measurements, exact comparison JSON and three lossless PNG copies.
- `m6-spatial-gpu-results.json` and `m6-spatial-gpu-evidence/identities.json`:
  parsed results and verified source/binary/shader/evidence snapshots.

This is an integration checkpoint, not a released or pinned library package.
